Expand description

Tasks can block waiting for a Blocker to notify them to retry an action.

User code should generally only call Blocker::block_until or CurrentTask::block_on.

Required Methods§

Source

fn should_try(&self) -> bool

Return true if performing the action may succeed and should be attempted. This must be very fast and cannot block for any condition itself. This is because it will be called inside the scheduler with locks held.

This should be an approximation of the success of a try_ function such as Consumer::try_consume. This must return true if trying would succeed, but may also return true spuriously even if it will fail.

This must have Acquire ordering.

Source

fn enqueue(&self, waker: &Arc<Waker>) -> WakerKey

Add a task to the wait queue of self. After this call, the task must be awoken if Self::should_try may return true again.

This must have Release ordering.

This returns an ID which can be passed to Self::remove (on the same instance) to improve the performance of removal.

Source

fn remove(&self, key: WakerKey)

Remove a task from the wait queue of self. After this call, the task will not be awoken when when should_try will return true. This undoes the effect of Self::enqueue.

Provided Methods§

Source

fn block_until<T>(&self, cond: impl Fn() -> Option<T>) -> T
where Self: Sized,

Block on self repeately until cond returns Some. This assumes that this blocker will be woken if cond() would change.

To block on multiple Blockers, use CurrentTask::block_on.
