Module locking

A simple implementation of a ostd::orpc::oqueue::OQueue using a ostd::sync::Mutexs. This is a baseline implementation that supports all features, but is also slow in many cases.

Structs§

CloningLockingConsumer 🔒
A consumer for a locking OQueue which does support observers. This clones values as they are taken out of the OQueue, to make sure they are still available for observers.
LockingConsumer 🔒
A consumer for a locking OQueue. This is only used for non-observable tables where the value should be moved out instead of cloned.
LockingOQueueInner 🔒
The mutex protected data in the locking OQueue implementations.
LockingProducer 🔒
A producer for a locking OQueue. The same is used regardless of observation support.
LockingQueue 🔒
An OQueue implementation which supports Send-only values. It supports an unlimited number of producers and consumers. It does not support observers (weak or strong). It is implemented using a single lock for the entire OQueue.
LockingStrongObserver 🔒
A strong observer for a locking OQueue. This will clone values and works only with CloningLockingConsumer.
LockingWeakObserver 🔒
A weak observer for a locking OQueue. This only works with ObservableLockingQueue since otherwise the values would have been moved out instead of cloned.
ObservableLockingQueue 🔒
An OQueue implementation which supports Send + Clone values and supports observation. It also supports and unlimited number of producers and consumers. It is implemented using a single lock for the entire OQueue.
